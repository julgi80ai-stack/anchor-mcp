# Anchor

**AI가 인터넷에서 얻은 정보의 시간적·출처적 무결성 계층**

*기술 소개서 및 설계 철학 · 2026 · 개정 2판*

---

## 0. 한 문장

> **Anchor는 AI가 사용한 웹 근거를 시간에 걸쳐 다시 검증할 수 있게 한다.**

이 문장 하나가 프로젝트의 전부다. 여기서 벗어나는 기능 요구가 들어오면, 그것은 다른 프로젝트다.

---

## 1. 지금 인터넷의 구조

```
AI → 웹 → 정보 → 답변
```

이 흐름은 잘 작동하는 것처럼 보인다. 그런데 AI가 인터넷을 **일회성이 아니라 지속적으로** 사용하기 시작하면, 이 화살표들 사이에서 아무도 답하지 않는 네 개의 질문이 생긴다.

1. **그 답변은 언제 가져온 정보인가?**
2. **AI가 인용한 문장이 실제로 원문에 있었나?**
3. **그 페이지가 지금도 그렇게 말하고 있나?**
4. **지난달에 사용한 근거를 다시 확인할 수 있나?**

네 질문은 모두 **시간**에 관한 것이다. 그리고 현재의 스택에는 시간을 담당하는 계층이 없다.

검색 엔진은 "지금 무엇이 있는가"를 답한다. 모델은 "그것이 무엇을 뜻하는가"를 답한다. **"그것이 언제부터 그러했고, 지금도 그러한가"는 아무도 답하지 않는다.**

Anchor는 그 자리에 있다.

---

## 2. 이름

웹의 링크는 원래 **앵커(anchor)** 라고 불렸다. `<a>` 태그의 a는 anchor다. 문서의 특정 지점에 닻을 내린다는 뜻이었다.

그런데 웹의 앵커는 **공간에 대한 좌표일 뿐, 시간에 대해서는 아무것도 보장하지 않는다.** 링크는 어제와 오늘 같은 곳을 가리키지만, 그곳의 내용이 같다고는 말해주지 않는다. 30년 동안 우리는 그것을 문제로 여기지 않았다. 사람이 링크를 열면 바뀐 걸 눈으로 알아채니까.

AI는 알아채지 못한다.

**Anchor는 링크에 시간 축을 되돌려주는 프로젝트다.** 닻은 배를 멈추지 않는다. 배가 움직여도 위치를 잃지 않게 할 뿐이다.

---

## 3. 계보 — 우리는 처음이 아니다

이것은 새로 발견한 문제가 아니다. 오래전에 정의됐고, 측정됐고, 표준까지 나왔다.

```
2009 ─── Memento 제안 — "웹은 기억력이 나쁘다"
2013 ─── RFC 7089 — HTTP에 시간 차원을 더하다
2014 ─── "다섯 편 중 한 편이 참고문헌 부패를 겪는다"
2015 ─── Time Travel 서비스 개시 (LANL)
2016 ─── "네 개 중 세 개의 참조가 바뀐 콘텐츠로 이어진다"
  ⋮
2025 ─── Time Travel 서비스 종료 ◀── 인프라 소멸
2026 ─── AI 에이전트가 웹을 대량 소비  ◀── 수요 폭증
         ▲
         └─ Anchor
```

**RFC 7089 (Memento)** 는 HTTP에 시간 차원을 추가한 표준이다. 원본 리소스, 과거 버전, 버전 목록, 시간 협상 — 웹의 과거에 접근하는 문법이 이미 13년 전에 완성되어 있었다.

그 표준을 실제로 굴리던 서비스가 로스앨러모스 국립연구소의 **Time Travel**이었다. 2015년부터 여러 웹 아카이브를 가로질러 과거 페이지를 찾아주던 공식 인프라. **2025년 말, 경영상의 결정으로 폐쇄됐다.** mementoweb.org는 자료만 남은 정적 사이트가 됐다.

이 순서를 다시 보자. **웹의 시간을 지키던 인프라가 문을 닫은 다음 해에, AI 에이전트가 그 어느 때보다 웹을 많이 읽기 시작했다.**

Memento는 틀려서 죽은 게 아니다. **기관 자금에 의존하는 중앙 서비스로 지어졌기 때문에 죽었다.** Anchor의 로컬 우선 설계는 그 실패 모드에 대한 직접적인 답이다. 서버가 없으면 폐쇄될 서버도 없고, 예산 회의에서 사라질 항목도 없다.

> **Anchor는 새로운 것이 아니라 돌아온 것이다.
> 다만 이번에는 서버가 아니라 당신의 디스크 위에서.**

Anchor는 Memento의 용어를 쓰고, RFC 7089 형식으로 버전 목록을 내보내고, W3C Web Annotation의 선택자 모델로 인용을 표현하고, Robust Links 규약으로 각주를 만든다. 표준을 새로 만들지 않는다. **이미 있는 것을 에이전트가 쓸 수 있게 조립한다.**

## 4. 무엇과 경쟁하지 않는가

이것이 Anchor의 가장 중요한 전략적 자산이다.

```
   Agent A ─┐
   Agent B ─┤
   Agent C ─┼──▶  Anchor  ──▶  Web
   Agent D ─┤
   Agent E ─┘
```

**Anchor는 검색하지 않는다.**

- Google과 경쟁하지 않는다.
- Naver와 경쟁하지 않는다.
- Perplexity와 경쟁하지 않는다.
- OpenAI, Anthropic, 오픈모델 중 어느 쪽에도 종속되지 않는다.

그들이 정보를 **찾는다**. Anchor는 찾아온 정보를 **어떻게 신뢰하고 기억할 것인가**라는, 한 층 아래의 문제를 맡는다.

검색을 하지 않는다는 것은 결핍이 아니라 설계다. 검색을 하는 순간 Anchor는 수십 개 회사와 같은 링에 올라가고, 개인이 만드는 프로젝트로서는 즉시 죽는다. 검색을 하지 않기 때문에 Anchor는 **모든 검색의 아래에 깔릴 수 있다.**

> 위에서 싸우면 하나가 이긴다. 아래에 깔리면 전부의 밑에 있게 된다.

같은 이유로 Anchor는 모델을 만들지 않는다. 모델을 만들지 않기 때문에 모든 모델이 쓸 수 있다.

### 인접한 것들과의 구분

혼동하기 쉬운 세 가지가 있다. 축이 각각 다르다.

| | 그들이 묻는 것 | Anchor가 묻는 것 |
|---|---|---|
| **변경 감시 도구** | "이 페이지가 바뀌었나?" (미래) | "내가 인용한 문장이 아직 있나?" (과거) |
| **AI 인용 추적 도구** | "내 브랜드가 AI 답변에 나오나?" (인용되는 쪽) | "내가 쓴 근거가 유효한가?" (인용하는 쪽) |
| **참고문헌 검증 도구** | "이 논문이 실존하나?" (정적 문헌) | "이 웹페이지가 여전히 그렇게 말하나?" (변하는 웹) |

세 축 모두에서 Anchor는 반대편에 있다. 이 조합은 비어 있다.

## 5. 제품은 작게, 프로토콜의 철학은 크게

Anchor의 v1.0은 SQLite 파일 하나와 아홉 개의 도구다. 서버 클러스터도, 계정 시스템도, 대시보드도 없다.

이것은 야심이 작아서가 아니다. **인프라가 되는 물건들의 공통점이기 때문이다.**

| 프로젝트 | 처음 크기 | 지금 위치 |
|---|---|---|
| SQLite | 파일 하나짜리 임베디드 DB | 지구상에서 가장 많이 배포된 데이터베이스 |
| curl | HTTP 요청 하나 보내는 CLI | 거의 모든 기기 안에 있음 |
| Linux | 개인이 취미로 만든 커널 | 클라우드의 바닥 |

이들 중 어느 것도 "새로운 계층을 정의하겠다"는 백서로 시작하지 않았다. **만든 사람이 자기가 쓰려고 만들었고, 잘 만들었고, 남에게 줬다.**

그리고 리눅스는 POSIX를 발명하지 않았다. 규격은 이미 있었고, 리눅스는 그 규격의 자유로운 구현체였다. Anchor와 Memento의 관계가 정확히 그렇다.

## 6. 다섯 가지 원칙

### 원칙 1 — 로컬 우선 (Local First)

Anchor는 사용자의 기계에서, 사용자의 디스크에, 사용자의 데이터로 동작한다. 서버에 물어보지 않는다. 텔레메트리를 보내지 않는다. 인터넷이 끊겨도 캐시된 근거는 그대로 읽힌다.

근거를 검증하는 도구가 정작 자기 자신은 검증 불가능한 원격 서비스라면, 그것은 문제를 옮긴 것일 뿐이다. **그리고 원격 서비스는 폐쇄될 수 있다. 우리는 그 사례를 방금 봤다.**

### 원칙 2 — 사용자가 한 명이어도 이득 (Value at N=1)

네트워크 효과에 의존하는 기능은 v1.0에 넣지 않는다. 혼자 써도 페치가 줄고, 토큰이 줄고, 인용이 검증된다. 두 번째 사용자가 나타나지 않아도 첫 번째 사용자는 이미 이득을 봤다.

이것이 개인이 인프라를 만들 수 있는 **유일한** 경로다. 양쪽 동시 채택이 필요한 설계는 조직이 있어야 한다.

### 원칙 3 — 정직한 클라이언트 (Honest Client)

Anchor는 프록시를 돌리지 않고, 브라우저 지문을 위장하지 않고, robots.txt를 무시하지 않고, CAPTCHA를 풀지 않는다. **403은 403으로 보고한다.**

우회 기능을 하나라도 넣는 순간 Anchor는 스크래퍼가 되고, 인프라로서의 정당성을 잃는다. 인프라의 신뢰는 능력이 아니라 절제에서 나온다.

### 원칙 4 — 덜 가져가고 더 정확하게 쓴다 (Fetch Less, Cite Better)

Cloudflare의 2025년 중반 측정에 따르면, Google 검색 크롤러는 사람 방문 1건당 약 14페이지를 가져갔다. 같은 기준으로 OpenAI의 크롤러는 1,700:1, Anthropic은 73,000:1이었다. 그리고 AI 크롤러 트래픽의 절반 이상이 **변하지 않은 페이지를 다시 가져오는 데** 쓰인다.

웹이 AI에게 문을 닫고 있는 것은 이 비대칭 때문이다. 2026년 9월부터 Cloudflare는 광고 게재 페이지에서 에이전트 크롤러를 기본 차단한다.

Anchor는 조건부 요청과 본문 해시로 재페치를 제거한다. 이것은 사용자에게는 비용 절감이지만, **웹 전체로 보면 AI와 퍼블리셔의 관계를 착취에서 회계로 바꾸는 일이다.** Anchor를 쓰는 에이전트는 덜 가져가고, 가져간 것을 정확히 인용한다.

이 원칙은 도덕적 장식이 아니다. 문이 닫히는 세계에서 **정직한 클라이언트만 살아남기** 때문이다.

### 원칙 5 — 보이지 않아도 된다 (Invisible by Design)

AWS 서버 안에서 리눅스가 돌아가는 걸 아무도 의식하지 않는 것처럼, 에이전트가 인용을 검증할 때 Anchor의 이름이 화면에 뜰 필요는 없다.

**잘 되면 사람들이 이름을 몰라도 된다.** 그것이 실패가 아니라 그것이 목적이다.

## 7. 무엇에 반대하는가

브랜드는 무엇을 지지하는지가 아니라 **무엇에 반대하는지**로 정의된다.

Anchor가 반대하는 것은 하나다.

> **그럴듯함이 사실을 대체하는 것.**

AI가 만들어내는 가장 위험한 산출물은 틀린 답이 아니다. 틀렸는데 출처가 붙어 있고, 그 출처가 진짜 URL이고, 문장이 매끄러워서 **아무도 확인하지 않는 답**이다.

여기에는 세 가지 부패가 겹쳐 있다.

- **환각(hallucination)** — 원문에 없던 문장이 인용된다.
- **링크 부패(link rot)** — 출처가 사라진다.
- **인용 표류(citation drift)** — 링크는 살아 있는데 내용이 바뀐다.

세 번째가 가장 위험하다. 깨지지 않기 때문에 아무도 눈치채지 못한다.

그리고 이건 추측이 아니라 측정된 사실이다. 학술 논문이 참조한 웹 콘텐츠의 **약 75%가 3년 안에 어느 정도 변경**됐고, STM 논문 **다섯 편 중 한 편**이 참고문헌 부패를 겪는다는 것이 100만 개 이상의 참조를 분석한 결과다. 논문 제목이 그대로 우리의 문제 정의다 — *"네 개 중 세 개의 참조가 바뀐 콘텐츠로 이어진다."*

Anchor의 `ALTERED` 상태는 정확히 이것을 잡기 위해 존재한다.

Anchor는 AI를 의심하라고 말하지 않는다. **확인할 수 있게 만들라**고 말한다. 그리고 그 판단은 사람이 한다 — Anchor는 문장이 바뀌었다는 사실만 보고할 뿐, 그것이 오탈자 수정인지 입장 번복인지는 판정하지 않는다.

## 8. 누구를 위한 것인가

| 대상 | 겪는 문제 | Anchor가 주는 것 |
|---|---|---|
| 논문·보고서를 쓰는 사람 | 3주 전 인용이 아직 유효한지 알 수 없다 | 제출 전 전체 인용 일괄 재검증 |
| 에이전트 개발자 | 같은 페이지를 매 세션 다시 긁는다 | MCP 도구 하나로 캐시·출처 확보 |
| 리서치 팀 | "이 숫자 어디서 나왔죠"에 답할 수 없다 | 인용 시점의 원문 스냅샷 보존 |
| 규제·감사 대응 | AI 산출물의 근거 추적 요구 | 페치 시각·해시·버전 이력 |
| 퍼블리셔 | AI 트래픽이 부하만 남긴다 | 조건부 요청을 지키는 클라이언트 |

첫 번째 사용자는 만든 사람 자신이다. 그 사실을 숨기지 않는다.

## 9. 왜 지금인가

2026년 중반, 에이전트 프로토콜 스택은 아래에서부터 굳어졌다.

- **MCP** — 에이전트와 도구 사이. 사실상 결착.
- **A2A** — 에이전트와 에이전트 사이. 중립 거버넌스 하에 1.0.
- **WebMCP** — 에이전트와 웹사이트 사이. W3C 초안, 브라우저 프리뷰.

세 계층이 답하는 질문은 모두 **"어떻게 접근하는가"** 다.

**"접근해서 얻은 것을 어떻게 시간에 걸쳐 신뢰하는가"** 는 어느 계층도 답하지 않는다.

동시에 세 가지가 겹쳤다.

1. **인프라가 사라졌다** — 이 문제를 20년간 담당하던 Memento Time Travel이 2025년 말 폐쇄됐다.
2. **웹이 닫히고 있다** — Cloudflare 기본 차단, Pay Per Use. 이미 가져온 것을 잘 보관하는 쪽이 유리해진다.
3. **수요가 폭증했다** — 에이전트가 웹을 읽고, 그 산출물에 대한 근거 요구가 규제·감사·학술 전 방향에서 늘고 있다.

빈자리와 수요가 같은 해에 만났다. 지금이 아니면, 이 자리도 누군가의 사유 서비스가 된다. 그리고 사유 서비스는 다시 닫힌다.

## 10. 성공의 정의

사용자 수도, 별 개수도, 투자 유치도 아니다.

> **누군가 다른 언어로 Anchor를 재구현할 때.**

그 순간 Anchor는 소프트웨어에서 규격이 된다. 그래서 스펙 문서는 짧고 명확해야 하고, 상태 코드는 일곱 개를 넘지 않아야 하고, 저장 포맷은 남이 읽을 수 있어야 한다. 재구현하기 쉽게 만드는 것이 곧 전략이다.

그 전 단계의 지표는 이렇다.

1. 만든 사람이 실제 보고서 작업에 매일 쓴다 (v0.3)
2. 30일 캐시 히트율 80% 이상 — 도구가 스스로 존재 이유를 증명 (v0.4)
3. 만든 사람이 아닌 누군가가 이슈를 연다
4. 만든 사람이 아닌 누군가가 기능을 붙인다
5. 재구현이 나타난다

## 11. 메시지 자산

### 태그라인

**주력**
> Anchor — 근거는 시간이 지나도 근거여야 한다.

**대안**
> 링크에 시간 축을 되돌려준다.
> 웹의 시간을 지키던 인프라는 문을 닫았다. 이번엔 당신의 디스크 위에서.
> 찾는 건 그들에게. 기억하는 건 여기에.
> AI의 인터넷 기억, 그리고 출처 검증.

### 30초 (비전문가)

AI에게 뭔가를 물어보면 출처 링크를 달아줍니다. 그런데 한 달 뒤 그 페이지의 내용이 바뀌거나 사라져도 아무도 모릅니다. 실제로 학술 논문이 인용한 웹 페이지의 4분의 3이 3년 안에 바뀐다는 연구가 있습니다. Anchor는 AI가 가져온 웹 문서를 시점별로 보관하고, 인용한 문장이 지금도 원문에 그대로 있는지 언제든 다시 확인해 줍니다. 검색은 하지 않습니다. 검색은 이미 잘하는 곳이 많으니까요.

### 2분 (기술자)

Anchor는 MCP 서버로 동작하는 로컬 우선 페치 캐시입니다. 세 가지를 합쳤습니다. 첫째, 조건부 요청과 본문 해시 기반 캐시 — 원본 바이트가 아니라 정규화된 본문으로 해시하므로 광고나 타임스탬프 노이즈에 속지 않습니다. 둘째, 버전 보존 — 문서가 바뀌면 새 스냅샷을 남기고, 인용이 참조하는 버전은 절대 삭제하지 않습니다. RFC 7089 TimeMap 형식으로 내보낼 수 있습니다. 셋째, 앵커 — W3C Web Annotation의 Selector 모델로 인용문의 앞뒤 문맥을 함께 저장해서, 문서가 바뀌어도 그 문장을 다시 찾아냅니다. 결과는 일곱 가지 상태로 나옵니다. 그대로, 이동됨, 수정됨, 사라짐, 문서 자체가 없어짐, 확인 불가, 판정 보류. 이 중 `ALTERED`와 `MISSING`의 구분이 실사용 가치의 대부분입니다. 저장소는 SQLite 파일 하나고, 모델을 부르지 않으며, 안티봇 우회를 구현하지 않습니다. 새로 발명한 건 조립 방식뿐이고, 밑에 깔린 표준은 전부 남의 것입니다.

### 용어 규칙

| 쓴다 | 쓰지 않는다 | 이유 |
|---|---|---|
| reference rot | — | Klein/Van de Sompel 계보의 정확한 용어 |
| citation drift | content drift | "content drift"는 개발자 사이에서 ML 개념 표류를 뜻한다 |
| 인용 표류 / 참고문헌 부패 | — | 한국어 표기 |

### 쓰지 않을 표현

브랜드 일관성을 위해 아래 표현은 문서·README·발표에서 사용하지 않는다.

| 금지 | 이유 |
|---|---|
| "AI 검색", "차세대 브라우저" | 경쟁 구도를 잘못 만든다. Anchor는 검색하지 않는다 |
| "혁명", "패러다임 전환", "게임 체인저" | 인프라는 이런 단어로 말하지 않는다 |
| "세계 최초", "새로운 표준" | **사실이 아니다.** RFC 7089이 13년 전에 나왔다 |
| "완벽한 사실 검증", "환각 제거" | 과장이며 사실이 아니다. Anchor는 **확인 가능성**을 주지 진실을 판정하지 않는다 |
| "엔터프라이즈급", "무제한 확장" | v1.0의 실제와 다르다 |
| "AI를 믿지 마세요" | 공포 마케팅. Anchor의 태도는 의심이 아니라 확인이다 |

### 한 장 요약

| | |
|---|---|
| **무엇** | AI가 사용한 웹 근거의 시간적·출처적 무결성 계층 |
| **어떻게** | 조건부 캐시 + 버전 보존 + 인용 앵커 재검증 |
| **계보** | Memento(RFC 7089)의 로컬 클라이언트 구현 |
| **형태** | MCP 서버 + Python 라이브러리, SQLite 단일 파일 |
| **하지 않는 것** | 검색, 모델, 크롤링, 안티봇 우회, 텔레메트리, 의미 판정 |
| **경쟁자** | 없음 (의도적으로) |
| **라이선스** | Apache-2.0 |
| **성공 조건** | 다른 사람이 재구현한다 |

## 12. 감사

Anchor는 다음 사람들과 프로젝트 위에 서 있다. 이것을 문서 앞쪽에 두는 것이 이 프로젝트의 태도다.

- **Herbert Van de Sompel, Michael L. Nelson, Robert Sanderson** 외 — Memento / RFC 7089. 웹에 시간 차원을 도입한 원저작
- **Martin Klein, Shawn M. Jones** 외 — reference rot과 content drift의 실증 연구
- **W3C Web Annotation Working Group** — 인용 선택자 데이터 모델
- **Hypothesis** — 퍼지 앵커링의 실전 구현, 그리고 실패까지 공개한 정직함
- **Robust Links** — 인용 표기 규약

우리가 하는 일은 이것을 에이전트가 쓸 수 있게 조립하는 것이다. 그 이상을 주장하지 않는다.
