# ADR-0002 — 라이선스 및 재사용 정책

| | |
|---|---|
| 상태 | **승인 (Accepted)** |
| 결정일 | 2026-08-16 |
| 대체 | — |
| 관련 | THIRD-PARTY.md · NOTICE · SPEC.md §11, §12 · ADR-0001 |

> 이 문서는 **판단 기준**이다. 어떤 라이선스를 쓰고 있는지는 `THIRD-PARTY.md`에 있다. 새 의존성을 추가하거나 남의 코드를 가져올 때 이 문서의 원칙을 적용하고, 결과를 대장에 기록한다.
>
> 법률 자문이 아니다. 필자는 변호사가 아니며, 상업적 배포나 조직 도입 전에는 전문가 검토를 권한다.

## 결정 (요약)

1. Anchor는 **Apache-2.0**으로 배포한다.
2. 카피레프트(GPL / AGPL / LGPL / SSPL / BUSL) 구성요소를 **일절 포함하지 않는다.**
3. 남의 성과를 가져올 때는 **세 가지 방식** 중 하나를 명시적으로 선택한다.
4. 법적 의무를 넘어서 **크레딧을 단다.**
5. 준수는 사람의 기억이 아니라 **CI 게이트**로 강제한다.

## 원칙

### 원칙 A — 명세와 구현은 완전히 다르다

**RFC 7089(Memento), W3C Web Annotation Data Model, Robust Links, RFC 9110, RFC 9309는 구현하라고 만들어진 문서다.** 명세대로 코드를 짜는 데는 어떤 허락도 필요 없고, 로열티도, 라이선스 표기 의무도 없다. 표준의 존재 목적이 그것이다.

Anchor가 TimeMap을 직렬화하고, TextQuoteSelector 구조를 쓰고, `data-versiondate` 속성을 출력하는 것은 전부 자유다.

주의할 것은 하나 — **RFC 본문 텍스트의 전문 재배포**에는 IETF Trust 조건(BCP 78)이 붙는다. 인용과 참조는 문제없다.

> ADR-0001 D3에서 상호운용을 채택한 근거가 여기 있다. **설계의 절반이 법적 비용 0으로 확보된다.**

### 원칙 B — Apache-2.0 아웃바운드는 한 방향만 열려 있다

| 들일 수 있음 | 들일 수 없음 |
|---|---|
| MIT, BSD-2/3-Clause, ISC | **GPL-2.0 / GPL-3.0** |
| Apache-2.0 | **AGPL-3.0** |
| CC0, Unlicense | **LGPL** (정적 링크 시) |
| MPL-2.0 (파일 단위 유지 조건) | SSPL, BUSL 등 소스 사용 가능 라이선스 |

Apache 재단이 명시한 대로, **Apache-2.0 소프트웨어는 GPLv3 프로젝트에 포함될 수 있지만 그 반대는 안 된다.** 비호환은 한 방향으로만 성립한다. GPLv3 코드를 가져오면 Anchor 전체가 GPLv3이 되어야 하는데, 그러면 Apache-2.0 배포가 불가능해진다.

### 원칙 C — 알고리즘은 저작권 대상이 아니지만, 코드는 대상이다

Myers의 비트벡터 근사 문자열 매칭은 1999년 논문으로 발표된 **알고리즘**이다. 논문을 읽고 직접 구현하는 것은 자유다.

그 알고리즘을 구현한 **누군가의 코드**를 베끼면 그 코드의 라이선스가 적용된다. BSD/MIT면 저작권 고지를 남기면 되고, GPL이면 못 쓴다.

**실무 규칙: GPL 코드는 읽지도 않는다.** 읽고 나서 "직접 짰다"고 주장하면 파생저작물 논쟁이 생긴다. 논문과 permissive 구현만 참고한다. 이건 규칙이라기보다 습관이라, 문서로 남겨야 지켜진다.

## 재사용의 세 가지 방식

가져오는 방식은 셋이고, 법적 부담이 각각 다르다. **무언가를 가져올 때 먼저 이 셋 중 어디인지부터 정한다.**

```
┌─────────────────────────────────────────────────┐
│ 방식 1: 프로세스 분리 호출        부담 없음      │
│   → MemGator를 HTTP로 부른다                     │
├─────────────────────────────────────────────────┤
│ 방식 2: 알고리즘만 참조          부담 없음*     │
│   → 논문/설명 문서를 보고 직접 구현              │
│   * 단, GPL 소스는 읽지 않는다                   │
├─────────────────────────────────────────────────┤
│ 방식 3: 코드 이식               고지 의무 발생   │
│   → permissive 코드를 번역/개작                  │
└─────────────────────────────────────────────────┘
```

### 적용 1 — MemGator는 방식 1

MIT이므로 포함해도 되지만 **포함하지 않기로 한다.** Go로 작성된 완성된 서버이고 TimeMap / TimeGate / Memento 엔드포인트를 이미 제공한다. Anchor는 HTTP로 부르기만 한다. 라이선스 혼합 자체가 발생하지 않는다.

MemGator는 Time Travel API 호환 폴백 엔드포인트 `/api`를 제공한다 — **폐쇄된 LANL 서비스를 쓰던 도구들의 드롭인 대체로 설계되어 있다.** SPEC.md §5.2의 아카이브 폴백이 사실상 공짜로 완성된다.

#### 운영 제약 (필수)

| 항목 | 지침 | 사유 |
|---|---|---|
| `--spoof` | **절대 사용 금지** | 무작위 user-agent 위장. 원칙 3(정직한 클라이언트)에 정면 위배 |
| `--agent` | Anchor의 User-Agent와 일치시킨다 | 책임 소재를 흐리지 않는다 |
| `--arcs` | 명시적으로 지정한다 | 기본값이 `git.io` 단축 URL인데 해당 서비스는 2022년 종료 |

**우회 기능이 딸린 도구를 통합할 때는, 그 기능을 쓰지 않는다는 사실이 코드가 아니라 문서에 남아야 한다.**

### 적용 2 — 앵커 매칭은 방식 2

Hypothesis 계열 라이브러리는 전부 JavaScript다. 어차피 Python으로 다시 짜야 하므로 코드 이식이 아니라 알고리즘 참조가 자연스럽다.

가장 값진 자산이 법적 부담 0인 쪽에 있다는 점이 중요하다.

| 참조 대상 | 성격 | 부담 |
|---|---|---|
| Hypothesis "Fuzzy Anchoring" 블로그 | 설계 설명 | 없음 |
| W3C Workshop 보고서의 4단계 절차 | 공개 표준 문서 | 없음 |
| Hypothesis client issue #3919 | 공개 이슈 트래커 | 없음 |
| anchor-quote 벤치마크 수치 | 공개 README | 없음 |
| Myers 1999 비트벡터 알고리즘 | 학술 논문 | 없음 |

"긴 문서 + 짧은 인용문에서 퍼지 매칭이 터진다"는 지식은 코드가 아니라 경험이고, 공개 이슈에 적혀 있다.

Hypothesis client 자체는 BSD-2-Clause이므로 이식해도 되지만, 그럴 경우 해당 파일에 원저작권 고지가 필요하다. 이식하지 않더라도 다음 주석을 다는 것을 권한다.

```python
# anchoring/matcher.py
#
# 매칭 전략의 단계 구성은 Hypothesis 클라이언트의 앵커링 접근을
# 참조했다 (BSD-2-Clause, Copyright (c) 2013-2019 Hypothes.is Project
# and contributors). 코드는 Python으로 새로 작성했으며, 근사 매칭
# 단계는 diff-match-patch 대신 편집거리 상한 방식을 쓴다.
```

법적 의무는 없다. 다는 이유는 아래 §"의무 이상의 크레딧"에 있다.

### 적용 3 — 근사 매칭은 방식 2, 필요 시 자체 구현

`regex` 모듈의 퍼지 매칭(`{e<=k}`)을 쓰면 직접 구현이 필요 없다. 제거가 필요해지면 Myers 논문을 보고 짠다. JS 구현(`approx-string-match`)은 동작 대조용으로만 쓰고, 코드를 줄 단위로 옮기지 않는다.

## 발견된 충돌 — `trafilatura`

**조사에서 실제로 걸린 유일한 문제다. 기록해 둘 가치가 있다.**

trafilatura는 v1.8.0 릴리스에서 **GPLv3+ → Apache-2.0으로 라이선스를 변경**했다. 현재 배포본(2.2.0)은 Apache-2.0이다.

문제는 이것이 **본문 추출 핵심 의존성**이라는 점이다. 하한을 명시하지 않으면 사용자 환경에 1.8.0 미만이 설치될 수 있고, 그 순간 Apache-2.0 프로젝트가 GPLv3 라이브러리에 의존하는 구조가 된다.

```toml
"trafilatura>=1.8.0",   # v1.8.0 미만은 GPLv3+. 기능이 아니라 라이선스 요구다.
```

### 여기서 배운 것

> **라이선스는 바뀐다. 사람의 기억으로는 못 막는다.**

의존성이 하나 늘 때마다 위험이 늘고, 트랜지티브 의존성은 눈에 보이지도 않는다. 그래서 §"강제 수단"의 CI 게이트를 결정했다.

## 특수 처리 두 건

두 패키지는 단일 라이선스가 아니다. 선택과 파급 효과를 기록한다.

### `regex` — `Apache-2.0 AND CNRI-Python`

CNRI-Python(Python 1.6 라이선스)은 OSI 승인 permissive이므로 Apache-2.0 배포에 문제없다.

**파급 효과 하나**: CNRI-Python은 GPLv2와 호환되지 않는 것으로 분류된다. 즉 **Anchor 전체를 훗날 GPLv2로 재라이선스하는 경로는 이 의존성 때문에 막힌다.** Apache-2.0을 유지하는 한 무관하지만, 기록해 둔다. 제거가 필요해지면 Myers 자체 구현으로 대체 가능하다.

### `blake3` — `CC0-1.0 OR Apache-2.0`

선택형 이중 라이선스. **Apache-2.0 쪽을 선택한다.**

근거 둘: 배포 라이선스와 일치시키는 편이 고지 처리가 단순하고, 일부 조직이 CC0의 특허 조항 부재를 문제 삼는다. 선택 사실을 `NOTICE`에 명시한다.

## 테스트 데이터 — 코드와 다른 종류의 제약

SPEC.md §12에서 공개 주석 데이터를 벤치마크에 쓰기로 했는데, 여기에는 라이선스와 다른 문제가 있다.

| 항목 | 쟁점 |
|---|---|
| Hypothesis 주석 텍스트 | 소프트웨어가 아니라 **사용자 생성 콘텐츠**다. 저장소의 BSD 라이선스가 적용되지 않는다 |
| 주석이 달린 원본 웹페이지 | 각 사이트의 저작물. 픽스처로 커밋하면 재배포가 된다 |
| API 이용 조건 | 대량 조회 시 서비스 약관 확인 필요 |

### 결정 — 픽스처 3등급 (SPEC.md §12.1)

| 등급 | 용도 | 출처 | 커밋 |
|---|---|---|---|
| A | 골든 (추출 정확도) | 퍼블릭 도메인, CC 문서, 본인 소유 | ✅ |
| B | 변형 (7상태 판정) | A등급에 프로그램으로 변형을 가한 합성 | ✅ |
| C | 앵커 벤치마크 (성능) | 공개 주석 데이터 런타임 수집 | ❌ 스크립트만 |

C등급을 커밋하지 않는 것이 핵심이다. Hypothesis의 `anchoring-test-tools`가 URL 목록을 입력받아 동작하는 방식이 정확히 이 패턴이며, 같은 구조를 따른다.

변형 테스트가 합성으로 충분하다는 점도 중요하다 — 원문에 광고 삽입·문단 이동·문장 수정을 프로그램으로 가하는 방식이므로 원본이 무엇이든 상관없다.

## 강제 수단

### NOTICE / THIRD-PARTY.md / SPDX

```
anchor-mcp/
├── LICENSE                    # Apache-2.0 전문
├── NOTICE                     # 저작권 고지, 이중 라이선스 선택 명시
├── THIRD-PARTY.md             # 대장
└── tools/audit_licenses.py    # 재현 가능한 감사
```

각 소스 파일 상단에 `# SPDX-License-Identifier: Apache-2.0` 한 줄. 자동 도구가 읽을 수 있고, 나중에 감사할 때 시간을 아낀다.

### CI 게이트 (SPEC.md §12.2)

| 검사 | 실패 조건 |
|---|---|
| 카피레프트 차단 | 의존성 목록에 GPL / AGPL / LGPL / SSPL / BUSL |
| `trafilatura` 하한 | 설치 버전 < 1.8.0 |
| `NOTICE` 동기화 | 새 런타임 의존성이 `THIRD-PARTY.md`에 없음 |

`tools/audit_licenses.py --fail-on-copyleft --check-floors`로 로컬·CI 양쪽에서 동일하게 실행한다.

## 의무 이상의 크레딧

법적으로는 BSD-2-Clause 코드를 참조만 하고 이식하지 않으면 고지 의무가 없다. 그래도 다는 이유는 전략이다.

이 분야는 좁다. Van de Sompel, Nelson, Alam, Klein, Jones, Knight — 20년간 같은 문제를 붙들어온 사람들이고 서로를 안다. **그들의 표준과 경험을 조용히 재구현한 프로젝트와, 명시적으로 계승을 선언한 프로젝트는 받는 대접이 완전히 다르다.**

전자는 무시당하거나 반발을 산다. 후자는 20년 치 신뢰를 빌려온다. NOTICE 파일 하나의 비용으로 살 수 있는 것 치고는 싸다.

ADR-0001 D1과 같은 논리이며, 여기서는 그것이 법적 형식이 아니라 자발적 선택임을 명시한다.

## 결과

### 긍정

- 카피레프트 오염 위험이 구조적으로 차단된다 (CI 게이트)
- 설계의 절반(명세 구현)이 법적 비용 0
- 라이선스 변경(trafilatura 같은)을 사람이 아니라 도구가 잡는다

### 부정 / 감수하는 것

- GPL 생태계의 좋은 라이브러리를 못 쓴다. 실제로 제약이 된 사례는 아직 없다
- `regex` 때문에 GPLv2 재라이선스 경로가 막혔다. Apache-2.0 유지 방침상 무관
- C등급 픽스처를 커밋하지 않으므로 벤치마크가 네트워크에 의존한다. CI에서 선택 실행으로 처리

### 이 정책을 다시 검토해야 할 때

- 새 의존성이 카피레프트이고 대체 불가능할 때
- Anchor를 다른 라이선스로 재배포해야 할 요구가 생길 때
- 공유 캐시(v1.3 후보)처럼 사용자 데이터를 교환하는 기능이 추가될 때 — 데이터 라이선스라는 새 축이 생긴다

위 상황에서는 이 문서를 고치지 말고 **ADR-0003 이후로 새로 쓴다.**
